Los dispositivos de E/S se comunican con la CPU a través de los buses de un sistema. Dado que son muy heterogéneos, sería muy costoso que la CPU los manejase directamente.

Los dispositivos están conectados a una pieza de hardware llamada **controlador de dispositivo** (a veces controladora o adaptador).
El controlador de dispositivo admite comandos abstractos de la CPU y se encarga de transmitirlos al dispositivo. Se libera a la CPU de tareas de muy bajo nivel.


El controlador de dispositivo actúa de interfaz entre la CPU y el dispositivo de E/S. Cada controlador puede ocuparse de uno o varios dispositivos del mismo tipo y se comunican con la CPU a través de unos registros o puertos, que generalmente incluyen:
- **Registros de control**: para enviar órdenes al dispositivo.
- **Registros de estado**: para obtener información del estado del dispositivo o controlador.
- **Registro de datos**: pueden ser de entrada, salida o bidireccionales.
	- Típicamente son registros de 1 a 8 bytes de tamaño.
	- Algunos controladores tienen chips FIFO que permiten almacenar pequeñas ráfagas de datos (buffers), mientras el host (CPU) no los puede recibir.

El controlador del dispositivo se encarga de:
- Coordinar el flujo de tráfico entre la CPU o memoria y el dispositivo periférico.
- Comunicación con la CPU: decodificación de comandos de la CPU, intercambio de datos de E/S con CPU, reconocimiento de dispositivos...
- Comunicación con el dispositivo: envío de comandos, intercambio de datos y recepción de la información de estado.
- Almacenamiento temporal de datos (buffer).
- Detección de errores.
