Existen tres métodos de realizar la E/S:
- **E/S programada (polling)**: la CPU se encarga de realizar todo el trabajo de E/S y solo es necesario programar cuando ejecutar cada operación concreta. La CPU le pregunta al dispositivo si está **listo** para poder escribir o leer datos. En caso de estar disponible, realiza la operación de E/S, sino el SO marca el recurso como ocupado y que se empleará tan pronto como se libere. La mayor **desventaja** de este método es que las operaciones de E/S ocupan la CPU por completo hasta que se terminen, por lo que hay una gran demora de tiempo si se necesitan realizar otras tareas.
- **E/S controlada por interrupciones**: el dispositivo avisa a la CPU de que requiere atención mediante una **interrupción**. Cuando llega la interrupción, se envía el primer bloque de datos para escribirse tan pronto como el recurso esté libre. Después, la CPU comprueba su planificador de tareas y ejecuta el siguiente proceso en la cola de Listos, pasando a estado Bloqueado el proceso encargado de escribir en el dispositivo. Cuando el dispositivo ha realizado la escritura y está listo para recibir el siguiente bloque, genera una interrupción. El gestor se encarga de detener el proceso actual y carga el proceso Bloqueado para continuar con la escritura de datos. Una vez finalizada la operación, se continúa ejecutando en CPU el proceso guardado anteriormente. Por lo general, cada driver tiene incluida una RTI, la cual se almacena como un array donde cada índice es una interrupción del sistema concreta y que contiene un puntero a la rutina (código) a ejecutar en caso de recibir dicha interrupción.  
- **E/S con DMA**: se trata de emplear el método de **polling** desde un controlador ajeno a la CPU. El controlador de DMA se encarga de transferir los datos al dispositivo, así como de gestionar su espacio de direcciones y controlar el bus de datos del sistema. La CPU debe proporcionarle el tipo de operación de E/S, la cantidad de bytes necesarios y las direcciones de memoria que debe emplear para obtener los datos. Los tipos de DMA son:
	- **DMA por ráfagas**: la CPU envía los datos a la DMA y esta se hace con el control del bus de datos. Usa el bus para enviar los datos a los registros del dispositivo de E/S. Mientras tanto, la CPU no puede continuar ejecutando instrucciones porque no puede cargar el código desde memoria, ya que el bus lo está usando la DMA. Por lo contrario, sí que puede ejecutar los datos que tiene en memoria caché.
	- **DMA por robo de ciclos**: cada vez que la DMA necesita el bus, roba un ciclo cada n ciclos de CPU, de modo que al transcurrir n ciclos, la DMA controla el bus. La DMA transfiere la información en bloques pequeños y, cuando finaliza con un bloque, devuelve el control del bus a la CPU. Si no ha terminado la transferencia, roba otro ciclo hasta completarla.
	- **DMA transparente**: la DMA solo emplea el bus de datos cuando la CPU no lo está usando. Se denomina transparente porque se conoce quién está usando el bus en cada momento.
